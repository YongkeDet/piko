# 主页批量下载与设置重组

新增补丁 `NewX: Download all profile media` 针对 `com.twitter.android` 的
`12.34.0-prod.01 / 312340001 / arm64-v8a`，最低 Android 10。

## 使用入口

保留默认选择的主页批量下载、照片画廊、行内下载补丁。安装后，先到
**Piko 设置 → 下载与保存 → 保存位置与文件命名** 分别选择图片、视频目录。
打开某个用户主页的 **媒体 → 照片**，点击画廊上方的
**下载此主页全部图片和视频**。该主页需要同时提供照片和视频两个标签页。

任务会先遍历照片，再自动切换到视频，逐页下载；结束或取消后恢复原来的标签页。
窗口显示读取页数、发现、已保存、跳过与失败数量，支持取消；取消保留已经保存的文件。
任务运行期间保持该页面在前台。最多同时排入四个文件，上一页的下载处理完成后再请求下一页。
任务期间暂停这两条媒体流的自动播放，避免切换到视频后在进度窗口后面播放声音。

下载沿用现有图片/视频目录、文件命名模板、按作者建文件夹、画质和同名文件策略。
“每次询问”在批量模式中使用最高可用画质，避免逐文件询问。
同一次任务内会对媒体链接去重；跨次重试是否跳过已有文件由重名策略决定，默认是跳过。

“全部”指 X 当前允许该账号读取并通过分页返回的媒体；已删除或没有访问权限的内容无法下载。
网络错误、游标循环或 45 秒没有分页进展均以“未完成”结束，不显示全部完成。
只有照片、视频两条列表都到达原生结束状态后，才显示遍历完成；单个文件失败会单独计数。
批量成员不重复显示成功 Toast，最终结果使用结果窗口和顶部横幅。

## 原生契约与实现

原始 APKM 的 SHA-256 为
`016a7eb2b6d8e2d6410da7f3c60e1bb46b002f6fedd797e366b068fb2897682b`。
分析以该文件的 DEX 为准，不使用其他版本的混淆名称。

- 复用原生主页组合组件切换照片、视频，复用原生底部分页器的请求事件及当前账号会话。
  没有另外实现 GraphQL 查询、登录或请求签名。综合媒体旧仓库也存在，但本实现使用当前主页
  已提供的两条媒体流，不改动用户的功能开关或原生媒体仓库缓存策略。
- 从持有底部分页器的 URT 组件解析底部 getter、StateFlow、回调捕获字段。
  协程也会捕获分页器字段，必须同时证明无参数的 paging-interface getter 读取该字段。
  从接受标签列表及照片/视频枚举的组合组件解析可用标签与切换接口。
  选中标签的字段通过原生当前组件 getter 中
  `field → StateFlow.getValue → cast to profile-tab enum` 的数据关系确定。
  不依赖构造器前一条指令仍是 `Boolean.FALSE`，以兼容同时启用默认帖子排序补丁的情况。
- 原生 profile renderer 实际把 `A(tab, sorting)` 返回的子 URT 组件传给时间线 UI。
  在组合组件的子组件创建/缓存返回点绑定 child → owner；回调先读自己的子组件，再按实例
  身份取父控制器。两端都是弱引用，不以“最近打开的用户”或 equals 代替绑定。
  读取内容时先调用父控制器的选中子组件 getter，再读取子组件的原生状态流；父级派生
  stateIn 在没有订阅者时可能保留旧值，不能仅轮询父级缓存作为下载内容。
- 切换标签后复用原生标签切换过程的 autoplay pause 调用；同时在 Success 模型的
  isAutoPlayAllowed 存储点限制批量任务期间的照片、视频自动播放，数据节省开关不变。
- 使用既有 `Success(timelineType=..., timelineItems=...)` 锚点读取媒体列表。
  返回列表前核对其 timelineType 与当前选中标签匹配，防止切换时消费另一条流的旧状态。
- 从 `BottomPagingState` 的标签解析 loading、cursorToUseForLoad 与网络事件字段。
  复用原画廊解析到的 canPage/isTerminated 与分页事件派发契约。
  原生 `NO_CURSOR` 与显式 `TERMINATED` 是两种结束情况：无游标只在已成功取回网络结果且
  没有加载下一页时有效。初始空状态不能据此判定完成。
- 底部分页与列表是不同的状态流；每个稳定快照先等待一秒，再处理本页。
  最后一页仍先下载，再判断该流结束。重复请求游标、加载中、失败与停滞都不能当成成功。
- 显示过滤前的列表绑定到**确切的原生 Success 实例**。过滤入口记录线程局部快照，
  构造器返回时才关联已初始化的实例，以弱引用键保留，实例释放后清理。
  不以过滤后列表的 equals 作为键，避免不同主页都被过滤成空列表时串用媒体。
  原生 Success 的 copy helper 仅在保留完全相同的 items 实例时继承过滤前快照；
  替换了列表的状态不能继承。这样自动播放、刷新状态变化后仍能读取过滤前媒体。
- 嵌套模块和模块项通过既有的模型访问桥展开。实际媒体 getter 和包装项解包复用画廊点击
  查看器解析出的媒体契约；不将照片包装项强行转换成普通帖子，也不添加运行时混淆反射。
- 文件请求继续由同一个 `InlineDownloadButton` 请求构造流程生成，使用已验证的
  `NewXDownloadFolders` 和共享下载引擎。正常单条下载的路径、反馈和重名行为保留。
  批量请求在入队前标记，成功、失败和取消由汇总窗口反馈。

原生类、字段、调用及寄存器都在修补时解析，新增注入通过 typed bytecode API 发射。
契约缺失或出现歧义时中止修补。新增补丁的兼容声明仅为此次提供并验证的 12.34 目标；
其他旧补丁的兼容声明和行为没有扩大。

## 设置结构

| 顺序 | 分类 | 内容 |
|---|---|---|
| 1 | 下载与保存 | 批量按钮、保存位置与命名、下载方式、画质与重名处理、媒体选择窗口 |
| 2 | 个人主页 | 标签编辑、默认媒体标签、照片画廊、帖子排序、主页浏览位置 |
| 3 | 时间线 | 刷新、浏览位置、标签与界面元素 |
| 4 | 内容过滤 | 广告、推荐、话题、AI、关键词、认证账号与社区笔记 |
| 5 | 帖子与互动 | 操作按钮、菜单、回复、翻译、投票、敏感媒体、播放与分享 |
| 6 | 导航 | 底部导航栏与侧边栏 |
| 7 | 外观 | 主题、字体与模糊效果 |
| 8 | 高级 | 功能开关、备份恢复、调试和更新记录 |

既有 setting ID、取值、默认值与备份节点保留，只改变归属和显示顺序。
原有 17 个下载设置仍全部注册；新增批量开关独立使用 `newx.downloads.profile_bulk`。
新字符串同时提供英文和简体中文；既有完整汉化检查继续运行。

## 验证范围

分页状态机测试针对最后一页先处理、空的中间页、无游标的成功空主页、
未成功请求的空状态、重复/循环游标、加载中和网络失败。
另有不同主页相同空过滤结果的实例隔离测试，以及嵌套媒体模块的展开测试。

构建、MPP/扩展来源、整包修补和最终 DEX 检查结果在对应的发布验证记录中填写。
本会话没有启动或操作手机；真实账号的完整分页、授权目录及取消交互仍需手机验证。
