# 固定底栏、禁止自动刷新新内容与下载进度

目标：X 12.34.0-prod.01 / 312340001，arm64-v8a，Android 10+。

## 设置

- **Piko 设置 → 时间线 → 禁止自动刷新新内容**：默认开启，沿用 `newx.timeline.disable_refresh`，保留已有配置。首页“为你推荐”“正在关注”及固定列表、话题、社区时间线已有内容时，不自动换入新帖子。首次加载、手动下拉刷新、向下翻页、主动更换主题过滤条件及帖子深链接继续可用。
- **Piko 设置 → 导航 → 固定底栏**：默认开启，修改后重启。滚动时保持手机主底栏显示，可与悬浮玻璃底栏同时开启。全屏/页面路由等外层隐藏条件继续由 X 控制；平板侧栏不在本补丁范围内。

更新后在 Morphe 刷新补丁源，重新载入默认选择，并使用原版 APKM 重新修补。新增两个默认选中的补丁：`NewX: Disable automatic content refresh`、`NewX: Fixed bottom navigation bar`。前者依赖已有自动刷新补丁，共用一个界面开关。

## 自动刷新契约

旧补丁只在 `AUTO_REFRESH` 且游标为空时阻止已有时间线刷新。目标 APK 的启动/恢复流程也会选择 `VIEWPORT_AWARE_AUTO_REFRESH`，其游标表示当前视口，仍然能下载新内容，不能把非空游标当成翻页证据。

新增门控放在原生 URT 仓库请求处理器入口，只检查两种自动请求，读取原生时间线类型与数据流中的页面后决定是否跳过。`PULL_TO_REFRESH`、`OLDER_THAN`、`NEWER_THAN`、`GAP` 直接走原有处理器。空数据（包括空页面）允许首次加载，个人主页、帖子详情、通知等其他时间线不受新增门控影响。深链接和主动改变“为你推荐”过滤条件保留已有的限时刷新许可。

请求类型、仓库实现、原生类型/数据访问器由现有语义指纹及其已验证的注入调用推导，不固定 R8 名称。新增补丁仅声明 12.34 兼容；旧补丁的执行逻辑及旧目标声明不变。

## 底栏契约

以保留字符串 `BottomBarOffsetAnimation` 解析手机底栏宿主，沿其创建的 scaffold 状态对象的 `isVisible` / `setVisible` / `getSize` 公共契约，追踪可见性字段、构造参数和宿主中的 Compose 状态读取。只在滚动状态拆箱后覆盖一个布尔值：原值为真或“固定底栏”开启时为真。

该位置位于路由/全屏隐藏条件之内。原有分支、状态写入、动画、布局高度、inset 和内容 lambda 保留；不会把整个 scaffold 强制显示，也不依赖玻璃样式补丁。使用 typed bytecode，插在 `move-result` 后，不迁移原生分支标签。

## 回归覆盖

- 自动刷新策略测试覆盖两种自动请求、手动刷新、三种分页请求、开关关闭、首次加载/空页面、其他时间线和显式导航许可。
- 底栏发射测试通过真实解析入口跟踪构造参数，验证原生外层隐藏分支跳过新增调用、结果寄存器正确，以及状态被重写时必须解析失败。
- 最终 APK 验证记录见 [构建与整包验证](newx-resolver-linter/x12.34-fixed-auto-refresh-2026-10-16.md)。

未操作用户设备；实际手机上的滚动、前后台切换和触控需用户安装后试用。

## 下载进度

普通图片、视频和 GIF 使用 Piko 下载引擎时，前台显示一个顶部进度卡：当前传输数量、百分比、文件名、已下载/总大小与速度。多项同时下载合并显示；大小未知时显示已下载大小和不定进度，不编造百分比。传输到 100% 但尚未保存完成时最多显示 99%，成功、失败或取消后移除该项。通知栏原有下载进度继续保留；成功反馈继续使用顶部横幅。

主页批量下载继续使用原进度窗口，增加当前最多四项传输的字节进度、速度和进度条，保留已发现/已保存/跳过/失败计数。百分比只表示当前传输队列，不表示尚未分页发现的全部媒体。前台卡在应用退到后台时移除，回到前台仍在下载时恢复，不需要悬浮窗权限。

适用范围为 Piko 下载引擎的普通及主页批量下载；外部下载器、X 未重定向的下载和合并长图的独立拼接流程使用各自的进度/状态反馈。
