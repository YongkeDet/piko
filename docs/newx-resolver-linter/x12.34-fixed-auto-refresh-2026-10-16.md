## 方法

先运行 CI 中的完整测试、Android MPP 构建、`:patches:lintNewxResolvers` 和 `:patches:checkExtensionDescriptors`。下载 artifact 后核对 archive digest、`source-provenance.json` 的源码 SHA 与实际 MPP SHA，当前 checkout 与构建源一致后才运行 `./patch-twitter.sh`。

所有修补都显式传入上述原始 APKM，使用 `--unsigned --continue-on-error --disable-purge --bytecode-mode FULL` 和 `PATCHER_OUTPUT_APK` 指定输出。全选另加 `--all-newx`，默认选择省略该项。单次顺序运行，不混用合并目录或旧包。

## APK 控制流与资源检查

独立检查最终 DEX：固定底栏只覆盖滚动状态的布尔值；去掉新增调用后，原宿主的每条 opcode、寄存器、引用、字面量和逻辑分支目标须与原版一致。自动刷新 classifier 只在仓库入口处理两种自动请求，手动/翻页与允许的初次加载都回到原有入口，门控不根据游标存在与否放行。

检查进度监听器由真实引擎注册、消费真实字节事件，完成/失败/取消均清理；主页窗口读取批量快照；合并长图读取 HTTP 长度与字节数，离开拼接流程时清理。所有新中文文案须在编译资源中与源文件一致。

复用玻璃底栏与既有下载/主页分页检查，保留原生 Haze 回退、系统安全区、作者目录、顶部保存反馈和批量恢复逻辑。模型测试覆盖并行、未知大小、重试重置、断网等待、晚到事件、保存前 99% 和独立长图任务 ID。

## 范围

新增两个 bytecode 补丁只声明精确 12.34 目标。旧自动刷新补丁的执行逻辑未改变；下载进度使用 API 29 已有的 Android 接口。其他旧目标未做整包验证。
