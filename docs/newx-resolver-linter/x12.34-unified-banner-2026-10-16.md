## APK 契约及改动

生产代码只使用语义、字段和调用关系解析。以下混淆名仅供复现侦察：API `com/x/inappnotification/api/a` 的 toString 连接 message、detailText、style、priority 字段。R8 移除了 action 构造参数，但 style 的默认掩码仍为 128，priority 为 256，detail 为 16，不能按现存参数下标计算。原构造器不变；新桥直接构造原生 Literal 和 notification。

`Show(entry=...)` 指向 entry `impl/s`，model accessor 连接 API 模型。manager `impl/q` 的静态 actor 在解包 Show 后调用 Object-only 桥。当前 entry、原生 present、dispose、dismiss 方法由真实字段/调用关系唯一确定。只为已验证的 12.34 增加默认公开补丁，旧目标继续使用旧桥与卡片适配器，不扩大兼容声明。

同一补丁的进度更新先 present 新 entry，再 dispose 旧 entry，避免 flow 经历中间 null；旧 entry 已不是 current，因此不会清除新横幅或取消新计时器。原生旧 AutoDismiss 事件按 entry 身份判断，不能关闭替代者。被丢弃的更新与清除控制 entry 也 dispose，以恢复 sender continuation。所有其他事件沿原路径运行。

弱引用与对象身份记录本扩展消息、种类和任务代次。错误 Error/High，成功 Success/Normal，进度 Default/Low；结果有 5 秒保护，进度让位于其他原生提示。终态后旧进度、旧代次清除和针对其他消息的清除均拒绝。跳过与主动取消不标成失败或成功。普通入队提示由实时进度取代，成功不再因系统通知开启而缺少应用内终态。

界面直接使用原生主文字与 detailText 层级；前台每秒最多更新一次，未知长度不伪造百分比。主页批量任务保留含取消操作的详细窗口。详见[设计说明](../newx-unified-download-banner.md)。

83 项补丁测试与 278 项扩展测试通过，失败/跳过为 0。API 29 lint、animalsnifferMain、解析器和扩展描述符检查通过。[测试计数](x12.34-banner-test-counts.json)。新增测试覆盖真实默认掩码错位、actor 消费事件跳转、并发替换、错误/结果保护、对象身份及代次清除。

命令（全选加入 `--all-newx`，默认省略，两个修补顺序执行）：

```sh
JAVA_TOOL_OPTIONS='-XX:-UsePerfData -Xshare:off' \
PATCHER_JAVA=/path/to/java21 MORPHE_CLI_JAR=/path/to/morphe-desktop-1.18.1-all.jar \
PATCHER_OUTPUT_APK=OUT.apk ./patch-twitter.sh ORIGINAL.apkm \
  [--all-newx] --unsigned --continue-on-error --disable-purge --bytecode-mode FULL
```

MPP 与 CI source-provenance 的 SHA、bundle 哈希及当前检出均由脚本验证。维护清理临时文件后，从同一原版 APKM 与同一 CI 构建恢复并重新顺序修补；下列报告来自恢复后的最终验证，没有发布任何临时失败或混用构建的 APK。
